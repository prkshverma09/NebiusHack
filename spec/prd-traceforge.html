TraceForge: capture frontier-model agent traces, distill them into small open models, prove parity on a live benchmark

A working clone of mubit.ai's core loop built entirely on Nebius Token Factory: an OpenAI-compatible trace-capture gateway sits in front of agent model calls, turns verified frontier-model behaviour into training data, fine-tunes a small open model via LoRA, and evaluates all three models on a held-out benchmark — showing a ~1–8B "Bonsai" model matching its frontier teacher at a fraction of the cost.

01Summary and the one-sentence pitch

Pitch: "Point any agent at our proxy. Every frontier-model call becomes training data. We fine-tune a small open model on the calls that worked — and prove on a live benchmark that it now does the frontier model's job at ~30× lower cost."

This is a faithful, hackable subset of Mubit's product: their "agentic runtime calibration" replaced by a concrete, measurable pipeline — capture → verify → distill → evaluate — with every number produced by a real API call or a real benchmark grade. Nothing in the demo is simulated.

Deliverable

Working API + dashboard: trace capture, dataset builder, fine-tune orchestrator, eval harness. Not a slideware story — judges watch a live re-grade.

Proof

Three benchmark bars on held-out data: base student, fine-tuned student, frontier teacher. Fine-tuned ≥ teacher (or within ~2 pts).

Fit

Hackathon asks to "put open models to work" and "test where today's models reach their limits" — this project is literally Nebius post-training as a product.

Budget

02Problem and users

The problem

  • Agent builders pay frontier prices forever — every repeated task re-pays the "intelligence tax" even though the task stopped changing months ago.
  • The raw material to fix it — the agent's own successful traces — is usually thrown away or locked in observability tools that end at dashboards.
  • Going from traces to a working distilled model means stitching together capture, grading, dataset formatting, fine-tuning, deployment and eval — days of plumbing before a single trained token.

Who it's for

  • Agent developers running the same task shape thousands of times (extraction, routing, tool calls, classification) who want frontier quality at open-model prices.
  • Hackathon judges — the persona that matters on the day. They need to see the loop close in under 3 minutes with real numbers.
  • Us — a reusable asset: the same gateway + distiller works for future projects (incl. ForgeAI's invoice domain).

Scope discipline for a one-day build. Mubit also does runtime calibration, memory recall, adapter refresh and rollback. TraceForge implements the proving half of that loop end-to-end (capture → distill → eval) and stubs the rest as roadmap. A closed loop that works beats a wide loop that's faked.

04System architecture

05The distillation loop (what actually happens)

  1. Capture. Benchmark runner agent calls POST /v1/chat/completions on TraceForge; gateway forwards to the teacher model on Nebius, streams the response back, and writes a trace row (messages, tools, tool_calls, usage, latency, cost) with a task fingerprint = hash(model + system + tools + response_format).
  2. Grade. Each trace is scored by the benchmark's checker — BFCL AST match or JSON field-equality — producing grade ∈ {correct, incorrect}. Only correct traces become "lessons".
  3. Build. Verified traces are normalised to OpenAI message format ({messages: [system?, user, assistant]}, assistant carries tool_calls where present), split ~90/10 into train/validation JSONL.
  4. Distill. JSONL uploaded via files.create; LoRA job created via fine_tuning.jobs.create (r=16, α=16, 3 epochs, packing); job polled to succeeded.
  5. Deploy. Checkpoint registered via POST /v0/models as a named model (e.g. bonsai-bfcl-v1); callable through the same chat-completions API.
  6. Prove. Eval harness runs the held-out test split through three model IDs — base student, Bonsai, teacher — grades identically, and renders the score table + $/call comparison.
  7. Switch. If Bonsai ≥ teacher − margin, route=auto points live traffic at the Bonsai endpoint; the gateway keeps logging, so the next distillation round starts from production data.

06Component specifications

6.1 Trace gateway proxy

OpenAI-compatible /v1/chat/completions (and /v1/models passthrough). Forwards to the configured upstream model, records request/response verbatim including the tools array and tool_calls, computes cost from a per-model price table, assigns session_id + task fingerprint. Fail-open: if logging fails the call still succeeds.

6.2 Trace store sqlite

Tables: traces, grades, datasets, finetune_jobs, eval_runs, eval_items. Single file, WAL mode, JSON columns decoded on read — same pattern as forgeai's db.py.

6.3 Grader truth-bound

Pluggable: BFCLGrader (AST comparison vs ground-truth function call), JSONMatchGrader (extraction fields). Grade stored with the checker's verdict detail — no LLM-as-judge for the headline metric.

6.4 Dataset builder curation

Filters grade=correct, dedupes by prompt hash, caps per-task balance, emits Nebius-compatible JSONL with validation split. Reports token count → cost preview before the job is submitted.

6.5 Distill orchestrator nebius

Wraps files.create → fine_tuning.jobs.create → poll → POST /v0/models. Stores job id, trained_tokens, status transitions. Sensible defaults; hyperparameters overridable per run.

6.6 Eval harness + dashboard proof

Runs the test split concurrently across model IDs, grades, persists per-item verdicts. Dashboard: live trace feed, dataset/job status, and the three-bar score chart with $/1M-token comparison — the demo's money shot.

08Benchmark & demo data plan

Selection criteria: (a) on-theme for "agent traces" — tool/function calling; (b) deterministic, automatable grading — no LLM judge for the headline number; (c) published precedent that small fine-tuned models reach frontier level, so the claim is credible; (d) fits one day.

Primary plan — BFCL slice. Use the AST-evaluated categories (simple, multiple, parallel, parallel_multiple, irrelevance): ~400–1,500 items. Split 70/30 — teacher generates traces on the train part only; the test part stays untouched until eval. Optional enrichment: Salesforce xlam-function-calling-60k as auxiliary training rows if teacher yield is low.

Why this demo lands. The headline isn't "we fine-tuned a model" — it's "a 1–8B open model now scores within noise of a 235B+/frontier teacher on real tool calls, at ~30× lower token cost, and the pipeline that produced it is the product." BFCL's public leaderboard precedent (xLAM-1B) makes that claim defensible rather than magical.

Deployment-path check (day-0 verification). The classic fine-tuning/ API (Llama family) supports serverless LoRA deployment. 11Functional & non-functional requirements

Functional

  • Must Proxy /v1/chat/completions losslessly — identical response bytes to calling upstream directly.
  • Must Persist full traces incl. tools/tool_calls verbatim, usage, latency, computed cost.
  • Must Deterministic grader per benchmark; grade persisted with verdict detail.
  • Must Dataset builder emitting valid Nebius fine-tune JSONL with train/val split.
  • Must Orchestrate upload → job → deploy entirely via API; surface job status.
  • Must Eval harness producing the 3-model score table on held-out items.
  • Should Router flag switching live traffic to Bonsai post-eval.
  • Should Dashboard: trace feed, job progress, score chart.
  • Could Streaming proxying; multi-task fingerprints; replay a trace against another model.

Non-functional

  • Must Nothing faked — every number is a measured grade or a real API response (same rule as ForgeAI). No mock mode in runtime code; test doubles live in tests/.
  • Must Gateway adds <50 ms overhead per call (local disk write only).
  • Must Secrets via env only (NEBIUS_API_KEY); never logged or rendered.
  • Should Single uvicorn process + one SQLite file; zero infra beyond Nebius.
  • Should Whole loop re-runnable via one command (make demo) for live-demo reliability.
  • Could Deterministic replay mode (recorded teacher responses) as demo fallback — clearly labelled, never scored.

12Success metrics (all measured)

≥ −2pts

Bonsai accuracy vs teacher on held-out test split. Target: parity or better; floor: within 2 points.

≥ +15pts

Bonsai vs its own base model. The distillation must visibly do something, not just inherit ability.

≥ 20×

$/M-token ratio teacher vs Bonsai, shown live. The business case in one number.

100%

Trace capture rate — every proxied call logged with usage + verdict. Observability table-stakes.

133-minute demo script

  1. The claim (20s). "Frontier models are the most expensive line item in every agent. We built a clone of Mubit on Nebius Token Factory: it turns your agent's own frontier-model calls into a small model that does the same job."
  2. Traces (30s). Dashboard live-feed: agent runs BFCL items through the gateway; expand one trace — show messages, tools, tool_calls, tokens, cost, grade badge.
  3. The pipeline (40s). Walk the architecture diagram; show dataset stats (verified traces → train tokens → est. cost), the finished Nebius job (trained_tokens, checkpoint), and the deployed bonsai-bfcl-v1 endpoint responding to a call.
  4. The receipts (60s). The score table: base 8B: 61% · bonsai-8b: 87% · teacher: 88% (numbers illustrative — real ones rendered live). Drill into 3 graded items where base failed and Bonsai now produces the correct tool call AST.
  5. The close (30s). "One line change to adopt: base_url. The model it builds is yours — open weights, deployed on Nebius. Everything you saw ran for under thirty dollars."

Live option: keep 20 held-out items aside; run the eval against the Bonsai endpoint in front of judges (~60–90s) so the score is computed in the room, not replayed.
